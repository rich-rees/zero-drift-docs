# 0047 — A store header says each key once and closes its quotes

**Date:** 2026-10-28 · **Status:** accepted · **Origin:** ZDD-9, from the ZDD-7 review campaign's CR-196 (Rich's calls: blessings and map pages both; it fails lint, so 0.13.0).

## Context

Blessing files and semantic-map pages open with a small header of
`key: value` lines, read by one minimal parser (`lib/frontmatter.mjs`). It
strips a value's quotes whenever the value starts and ends with *any* quote
character, so `importance: "high'` reads as `high`. And it keeps the last of
a key written twice, so `kind: copy` above `kind: extend` reads as
`extend`. Lint then judged the value the parser produced, and passed a
header that said something its author did not write: a blessing's `kind`,
a page's `type` (which makes it an app page that house rules apply to).

## Decision

1. **Lint fails a header that repeats a key, or opens a value with a quote
   and does not close it with the same one.** It names the file and the
   line, and for a quote what ZDD would have read. An apostrophe inside a
   value (`title: Bob's page`) is not a quote.
2. **Both stores with headers**: the blessing store and the semantic map.
3. **The parser's output does not change.** The check reads the raw
   header beside it (`headerProblems`), so no generated byte moves; the
   author fixes the line.

## Consequences

- A new lint failure, so a minor: 0.13.0 ([0035](0035-a-lint-failure-the-same-releases-upgrade-clears-or-names-is-a-minor.md)).
  The upgrade does not rewrite a header (which reading is right is the
  author's call); lint names each line, and the upgrade note says so. No
  adopter had such a header when it shipped.
- Map pages and blessings keep one parser and one reading; the check is the
  guard on it.

## Rejected

- **Warn only (a patch).** A warning scrolls past while the wrong reading
  keeps steering sessions.
- **Blessings only.** A map page's repeated `type:` changes what the page
  is, by the same fault.
- **A stricter parser** (refuse the file, or take the first key). Every
  generated artifact built from these headers could change bytes, and
  "which one did you mean" is the author's question, not the parser's.
